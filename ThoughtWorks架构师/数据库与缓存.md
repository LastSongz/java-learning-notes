# 数据库与缓存

> MySQL、PostgreSQL、Redis的核心概念

## MySQL

### InnoDB vs MyISAM

| 特性 | InnoDB | MyISAM |
|------|--------|--------|
| 事务 | ✅ | ❌ |
| 行级锁 | ✅ | ❌ |
| 外键 | ✅ | ❌ |
| 崩溃恢复 | ✅ | ❌ |
| 全文索引 | ✅ | ✅ |
| Count(*)快 | ❌ | ✅ |

### 索引类型

| 类型 | 使用场景 |
|------|---------|
| **B-tree** | 默认，适用于范围查询 |
| **Hash** | MEMORY引擎，适用于等值查询 |
| **Composite** | 多列组合查询，遵循最左前缀原则 |

```sql
-- 复合索引
CREATE INDEX idx_order ON orders(customer_id, order_date DESC);

-- 支持: WHERE customer_id = 1
-- 支持: WHERE customer_id = 1 AND order_date > '2024-01-01'
-- 不支持: WHERE order_date > '2024-01-01'
```

### 查询优化

```sql
-- 使用EXPLAIN分析查询
EXPLAIN SELECT * FROM orders WHERE status = 'pending';

-- 启用慢查询日志
SET GLOBAL slow_query_log = 1;
SET GLOBAL long_query_time = 2;
SHOW VARIABLES LIKE 'slow_query_log%';
```

## PostgreSQL

### 高级数据类型

```sql
-- JSONB - 二进制存储的JSON
CREATE TABLE products (
    id serial PRIMARY KEY,
    attributes jsonb
);

SELECT * FROM products WHERE attributes @> '{"color": "red"}';

-- 数组类型
CREATE TABLE users (
    email_addresses text[]
);

SELECT * FROM users WHERE 'john@example.com' = ANY(email_addresses);
```

### 索引类型

| 类型 | 适用场景 |
|------|---------|
| **B-tree** | 默认，等值和范围查询 |
| **GIN** | JSONB、数组、全文搜索 |
| **GiST** | 几何类型、范围类型 |
| **BRIN** | 大表自然物理顺序（如时间序列） |

```sql
-- GIN索引用于JSONB
CREATE INDEX idx_data ON api_logs USING GIN (data jsonb_path_ops);

-- BRIN索引用于时间序列
CREATE INDEX idx_logs_created ON logs USING BRIN (created_at);
```

### [[MVCC多版本并发控制]]并发控制

PostgreSQL使用MVCC（多版本并发控制）允许并发事务而不加锁。

**隔离级别**：
- READ UNCOMMITTED (实际同READ COMMITTED)
- READ COMMITTED (默认)
- REPEATABLE READ
- SERIALIZABLE

```sql
-- 查看当前隔离级别
SHOW transaction_isolation;

-- 设置隔离级别
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

## Redis

### 数据结构

| 结构 | 用途 | 示例 |
|------|------|------|
| **String** | 简单键值 | 缓存、计数器 |
| **Hash** | 对象字段 | 用户信息 |
| **List** | 有序列表 | 队列、任务列表 |
| **Set** | 无序唯一集合 | 标签、关注列表 |
| **ZSet** | 分数字排序 | 排行榜 |

```python
# String
r.set('user:1:name', 'Alice')
r.setex('session:abc', 3600, '{"user_id": 1}')  # TTL 1小时

# Hash
r.hset('user:1', mapping={'name': 'Alice', 'email': 'alice@example.com'})
r.hgetall('user:1')

# ZSet (排行榜)
r.zadd('leaderboard', {'Alice': 1000, 'Bob': 2500})
r.zrevrange('leaderboard', 0, 9, withscores=True)  # Top 10
```

### 缓存模式

**Cache-Aside (旁路缓存)**：

```python
def get_user(user_id):
    cache_key = f'user:{user_id}'
    cached = r.get(cache_key)
    
    if cached:
        return json.loads(cached)
    
    # 缓存未命中，从数据库读取
    user = db.query('SELECT * FROM users WHERE id = ?', user_id)
    
    # 写入缓存，TTL 5分钟
    r.setex(cache_key, 300, json.dumps(user))
    
    return user
```

**Write-Through (穿透写)**：

```python
def update_user(user_id, data):
    # 先写数据库
    db.execute('UPDATE users SET ...', user_id, data)
    
    # 立即更新缓存
    r.setex(f'user:{user_id}', 300, json.dumps(data))
```

### 持久化

| 模式 | 描述 |
|------|------|
| **RDB** | 定时快照，文件小，恢复快 |
| **AOF** | 追加每条命令，可配置fsync策略 |

```bash

```

## 面试常考问题

### Q: MVCC是怎么实现的？
> 每行数据有两个隐藏列（创建版本、删除版本），读事务看到的是快照版本，不会被其他事务阻塞。

### Q: Redis持久化选RDB还是AOF？
> 数据安全要求高选AOF（everysec或always），追求性能且可接受少量数据丢失选RDB。通常建议混合使用。

### Q: 聚簇索引和覆盖索引的区别？
> 聚簇索引是数据行的物理存储顺序，一张表只有一个；覆盖索引是查询只用索引字段就能完成，不需要回表。

### Q: Redis的Key过期策略有哪些？
> 惰性删除（访问时检查）、定期删除（定时扫描）、淘汰策略（maxmemory-policy）。
