## 对照结果

### 第1章 LangChain介绍

已覆盖：
- LangChain 的由来、定位和解决的问题
- 统一模型接口、模块化架构、Agent 与工具调用、记忆管理
- RAG、Agent、对话系统、数据处理、内容生成、多模态等使用场景
- DeepSeek + Agent 查询天气的快速上手案例

整理校准：
- 原始资料以 Chains、Memory 等旧版组件作为核心组件之一；本地笔记保留这些概念，但强调 LangChain v1.x 更应优先掌握 Models、Tools、Agents、Structured Output、Middleware、Streaming 和 LangGraph。
- 安装依赖中将 `dotenv` 校准为 `python-dotenv`，因为代码里 `from dotenv import load_dotenv` 来自 `python-dotenv` 包。
- 部署生态中将旧版 `LangServe` 口径补充为 LangGraph Platform / LangGraph Server 方向。

### 第2章 Models 模型

已覆盖：
- Model Class 与 `init_chat_model` 两种初始化方式
- `invoke()`、`stream()`、`batch()`、异步调用及消息类型
- 结构化输出：Pydantic、TypedDict、JSON Schema
- 模型工具调用：`bind_tools()`、手动执行工具、把工具结果传回模型
- Reasoning、Rate Limiting、Invocation Config

整理校准：
- 原始资料中方法名有 `asteam()` 这类笔误，本地统一为 `astream()`。
- 异步示例中补充 `asyncio.create_task(...)`，避免把“创建协程”误解成“请求已并发执行”。
- 多工具调用不应简单理解为“每次推理只能调用一个工具”。更准确是：部分模型一次可以返回多个 tool calls，但开发者仍要执行工具并管理后续循环。
- 补充 `init_chat_model("provider:model")` 写法，便于和新版文档对齐。

### 第3章 Agent 智能体

已覆盖：
- Agent 定义、ReAct 执行循环、LLM / 工具调用 / Agent 区别
- `create_agent` 静态模型、动态模型、动态提示词
- 工具创建：`@tool`、Pydantic 参数模型、JSON Schema
- 工具错误处理：`@wrap_tool_call`
- Agent 结构化输出：ProviderStrategy、ToolStrategy、直接传 schema、None
- Agent 异步调用与 7 种 stream mode

整理校准：
- “Agent 内置记忆系统”改为“可基于 LangGraph 状态、checkpoint / store 接入短期或长期记忆”。`create_agent` 默认有消息状态，但不等于自动拥有长期记忆。
- 补充工具定义注意事项：工具名、description、docstring、保留参数名 `config` / `runtime`。
- 原始资料中“直接传入 schema 在 1.0 以上不再支持”的说法不准确；本地保留官方 v1.x 口径：直接传 schema 仍支持，但生产项目推荐显式使用 ProviderStrategy 或 ToolStrategy。
- 异步 Agent 增加 `asyncio.gather(...)` 并发示例，避免只写顺序 `await`。

### 第4~5章 Agent 记忆

已覆盖：
- 短期记忆：线程范围记忆、`thread_id`、checkpointer、`AgentState`、自定义状态
- 短期记忆访问与修改：工具读取状态、工具返回 `Command` 更新状态、`before_model` / `after_model` 中间件
- 长上下文处理：Trim、Delete、Summarize、自定义策略
- 长期记忆：跨线程记忆、LangGraph Store、namespace / key、工具读写 `runtime.store`
- 综合案例：电商客服助手如何组合短期记忆、长期记忆、工具调用、摘要、错误处理中间件和流式输出

整理校准：
- 将原始大章节拆成 [[LC-07-Agent短期记忆]]、[[LC-08-Agent长期记忆]]、[[LC-09-Agent记忆综合案例]] 三篇，避免单篇过长。
- 统一使用 `InMemorySaver` 表达内存 checkpointer；生产环境推荐使用数据库型 checkpointer / store。
- 强调 `thread_id` 管短期会话状态，`namespace + key` 管长期跨会话记忆，两者不要混淆。
- 原始综合案例中直接传 Pydantic `context` 会出现序列化警告，本地笔记补充了更稳妥的处理建议。
