# LC-03 模型结构化输出与工具调用

> 约束大模型输出格式，让结果可以被程序精准解析；通过工具调用扩展模型能力边界

## 2.3 模型结构化输出

结构化输出可以约束大模型输出结果，使其符合预定义的数据结构（如 JSON、Pydantic 模型或字典），而不是任意自然文本。确保模型生成的结果能够被程序精准解析，并无缝集成到下游系统中。

### 2.3.1 定义输出结构的模式

LangChain 提供三种方式定义输出结构，都可通过 `with_structured_output` 方法返回结构化结果。

#### 2.3.1.1 Pydantic 模型【推荐】

使用 Python 的 Pydantic 库定义强类型数据模型，支持复杂嵌套结构。适合需要严格数据验证和复杂结构的场景。

Pydantic 是一个基于 Python 类型注解的库，通过在运行时强制执行类型提示确保数据的正确性。定义时创建继承自 `BaseModel` 的类，使用类型提示和 `Field` 函数声明字段。

**简单结构示例：**

```python
from pydantic import BaseModel, Field

class Movie(BaseModel):
    title: str = Field(description="电影标题")
    year: int = Field(description="上映年份")
    director: str = Field(description="导演")
    rating: float = Field(description="评分（10分制）")

# 设置模型结构化输出
model_with_structure = deepseek_llm.with_structured_output(Movie)

# 调用模型并获取结构化输出
resp: Movie = model_with_structure.invoke("给我介绍下电影《星际穿越》")
print(resp)
# 输出: title='星际穿越' year=2014 director='克里斯托弗·诺兰' rating=9.3
```

> 定义类型中字段的 `description` 强烈建议写上，帮助模型理解该字段应该存入什么样的数据。

**嵌套结构示例：**

```python
from typing import List

class Actor(BaseModel):
    name: str = Field(description="演员姓名")
    role: str = Field(description="饰演的角色")

class Movie(BaseModel):
    title: str = Field(description="电影标题")
    year: int = Field(description="上映年份")
    director: str = Field(description="导演")
    cast: List[Actor] = Field(description="演员列表")  # 嵌套列表
    rating: float = Field(description="评分")

structured_model = deepseek_llm.with_structured_output(Movie)
response = structured_model.invoke("请介绍电影《盗梦空间》")

print(f"电影名: {response.title}")
print(f"导演: {response.director}")
print(f"演员列表: {response.cast}")
# 演员列表: [Actor(name='莱昂纳多·迪卡普里奥', role='多姆·柯布'), ...]
```

#### 2.3.1.2 TypedDict

Python 3.8+ 的类型提示工具，为字典对象定义固定的键名和值类型。无需额外依赖，适合快速定义字典结构。

```python
from typing_extensions import TypedDict, Annotated

class MovieTypedDict(TypedDict):
    title: Annotated[str, "电影的正式名称"]
    year: Annotated[int, "电影的公映年份"]
    director: Annotated[str, "电影导演的全名"]
    rating: Annotated[float, "10分制评分"]

model_with_structure = deepseek_llm.with_structured_output(MovieTypedDict)
resp: MovieTypedDict = model_with_structure.invoke("给我介绍下电影《星际穿越》")
print(resp)
# 输出: {'title': '星际穿越', 'year': 2014, 'director': '克里斯托弗·诺兰', 'rating': 9.4}
```

> 返回类型是 `dict`（而非 Pydantic 的对象），访问字段用 `resp['title']`。

**嵌套结构：**

```python
from typing import TypedDict, List, Annotated

class Actor(TypedDict):
    name: Annotated[str, "演员姓名"]
    role: Annotated[str, "饰演的角色"]

class Movie(TypedDict):
    title: Annotated[str, "电影标题"]
    year: Annotated[int, "上映年份"]
    cast: Annotated[List[Actor], "演员列表"]
    rating: Annotated[float, "评分"]
```

#### 2.3.1.3 JSON Schema

提供标准的 JSON Schema 字典定义结构，跨语言友好，适合需要复杂数据约束的场景。

**JSON Schema 标准关键字：**

| 关键字 | 说明 |
|--------|------|
| `title` | 为 Schema 提供人类可读的标题（不能是中文） |
| `description` | 详细文字描述 |
| `type` | 数据类型：string, number, integer, boolean, object, array, null |
| `properties` | 定义对象中包含的属性及其类型和说明 |
| `required` | 必须存在的属性名数组 |

**简单结构示例：**

```python
json_schema = {
    "title": "MovieInfo",
    "description": "电影对象",
    "type": "object",
    "properties": {
        "title": {"type": "string", "description": "电影标题"},
        "year": {"type": "integer", "description": "上映年份"},
        "director": {"type": "string", "description": "导演"},
        "rating": {"type": "number", "description": "评分（10分制）"}
    },
    "required": ["title", "year", "director", "rating"]
}

model_with_structure = deepseek_llm.with_structured_output(json_schema)
resp = model_with_structure.invoke("给我介绍下电影《星际穿越》")
# 输出: {'title': '星际穿越', 'year': 2014, ...}
```

**嵌套结构（使用 array 类型）：**

```python
project_schema = {
    "title": "MovieInfo",
    "type": "object",
    "properties": {
        "title": {"type": "string", "description": "电影标题"},
        "cast": {
            "type": "array",
            "description": "演员列表",
            "items": {
                "type": "object",
                "properties": {
                    "name": {"type": "string", "description": "演员姓名"},
                    "role": {"type": "string", "description": "演员角色"}
                },
                "required": ["name", "role"]
            }
        },
        "rating": {"type": "number", "description": "评分"}
    },
    "required": ["title", "cast", "rating"]
}
```

### 2.3.2 获取结构化结果的方式

#### 方式一：with_structured_output【首选】

最新、最简洁的 API，直接让模型"理解"你需要的数据结构并返回解析好的对象。

```python
model_with_structure = deepseek_llm.with_structured_output(Movie)
resp = model_with_structure.invoke("给我介绍下电影《星际穿越》")
# resp 直接是 Movie 对象
```

传入 `include_raw=True` 可同时获取原始 AI 消息对象（包含令牌用量等元数据）：

```python
model_with_structure = deepseek_llm.with_structured_output(Movie, include_raw=True)
resp = model_with_structure.invoke("给我介绍下电影《星际穿越》")
# resp 是字典，包含 'raw'、'parsed'、'parsing_error' 三个键
```

> 注意：部分国内大模型不支持此方式（如 `deepseek-reasoner`），此时考虑使用输出解析器。

#### 方式二：输出解析器

更传统的方式，通过提示词指导模型输出特定格式文本，再用解析器转换。流程：**提示词引导 → 模型生成文本 → 解析器转换**。

```python
from langchain_core.output_parsers import JsonOutputParser
from langchain_core.prompts import ChatPromptTemplate

# 定义结构
class Movie(BaseModel):
    title: str = Field(description="电影标题")
    year: int = Field(description="上映年份")

# 创建解析器和提示模板
parser = JsonOutputParser(pydantic_object=Movie)
prompt = ChatPromptTemplate.from_template("""
回答用户问题。
问题：{question}
你必须始终输出一个包含title(电影标题)和year(上映年份)的 JSON 对象。
""")

# 创建链（LCEL 管道）
chain = prompt | deepseek_reasoner_llm | parser

# 调用
response = chain.invoke({"question": "介绍电影《盗梦空间》"})
print(response)  # {'title': '盗梦空间', 'year': 2010}
```

### 三种定义模式对比

| 特性 | Pydantic（推荐） | TypedDict | JSON Schema |
|------|-----------------|-----------|-------------|
| 返回类型 | Pydantic 对象 | dict | dict |
| 类型安全 | 强 | 中 | 中 |
| 嵌套支持 | 好 | 好 | 好 |
| 额外依赖 | pydantic | 无 | 无 |
| 适用场景 | 严格验证、复杂结构 | 快速定义、轻量 | 跨语言、复杂约束 |

## 2.4 模型工具调用（了解）

大模型工具调用（Tool Calling / Function Calling）可以扩展模型能力，使模型能够突破纯文本生成的限制，与外部系统和功能进行交互。

### 2.4.1 模型调用工具步骤

**定义工具：**

```python
from langchain.tools import tool

@tool
def get_weather(location: str) -> str:
    """获取指定位置的天气"""
    return f"{location}的天气是晴朗的。"
```

**绑定工具并调用：**

```python
# 1. 模型绑定工具
model_with_tools = deepseek_llm.bind_tools([get_weather])

# 2. 模型生成工具调用请求
response = model_with_tools.invoke("北京今天天气如何？")
```

> 模型返回的 `AIMessage` 中只包含工具调用信息（工具名称和参数），**不会主动调用工具**。

**完整的四步调用流程：**

1. **模型绑定工具**：通过 `model.bind_tools([...])` 绑定工具
2. **模型生成工具调用请求**：模型返回工具调用信息
3. **开发者手动执行工具**：从响应中提取信息并调用对应工具
4. **将工具结果传递给模型**：模型根据结果生成最终回复

```python
from langchain_core.messages import HumanMessage

messages = []
messages.append(HumanMessage(content="北京的天气"))

# 2. 模型生成调用工具请求
response = model_with_tools.invoke(messages)
messages.append(response)

# 3. 根据模型响应调用工具
for tool_call in response.tool_calls:
    if tool_call['name'] == 'get_weather':
        tool_result = get_weather.invoke(tool_call)
        messages.append(tool_result)

# 4. 模型根据工具结果生成最终响应
final_response = model_with_tools.invoke(messages)
print(final_response.content)
# 输出: 根据查询结果，北京目前的天气是晴朗的。
```

> 大模型调用工具是**单次推理**，直接响应，需要开发者手动执行工具并管理循环。

### 2.4.2 模型多工具调用

大模型每次推理只调用一个工具，调用多个工具时需要用循环管理多次调用。

```python
@tool
def get_stock_price(company: str, timeframe: str = "today") -> str:
    """获取指定公司的股票价格信息"""
    mock_data = {
        "苹果公司": {"today": 185.20, "week": 183.50},
        "微软公司": {"today": 415.86, "week": 412.30},
    }
    # ...返回价格信息

@tool
def search_news(company: str) -> str:
    """搜索指定公司的财经新闻"""
    # ...返回新闻列表

# 绑定多个工具
tools = [get_stock_price, search_news]
model_with_tools = deepseek_llm.bind_tools(tools)

message = [HumanMessage(content="苹果公司今天的股价是多少？最近有什么新闻？")]

# 用循环管理多工具调用
while True:
    response = model_with_tools.invoke(message)
    message.append(response)

    if response.tool_calls:
        for tool_call in response.tool_calls:
            if tool_call["name"] == "get_stock_price":
                result = get_stock_price.invoke(tool_call)
                message.append(result)
            if tool_call["name"] == "search_news":
                result = search_news.invoke(tool_call)
                message.append(result)
    else:
        break  # 没有工具调用，说明模型已生成最终答案

print(response.content)
```

## 2.5 模型其他使用

### 2.5.1 Reasoning — 模型推理

大模型的"推理"能力指处理复杂问题时进行逻辑链式思考和多步骤分析。如果底层模型支持推理（如 deepseek-reasoner、openai o1/o3），可以在输出中显示推理过程。

```python
deepseek_llm2 = init_chat_model(
    model="deepseek-reasoner",
    model_provider="deepseek",
    api_key=DEEPSEEK_API_KEY,
    base_url=DEEPSEEK_BASE_URL,
)

# 非流式获取推理过程
response = deepseek_llm2.invoke("10个字解释为什么天空是蓝色的？")
reasoning_steps = [b for b in response.content_blocks if b["type"] == "reasoning"]
print(" ".join(step["reasoning"] for step in reasoning_steps))

# 流式获取推理过程
for chunk in deepseek_llm2.stream("10个字解释为什么天空是蓝色的？"):
    reasoning_steps = [r for r in chunk.content_blocks if r["type"] == "reasoning"]
    print(reasoning_steps if reasoning_steps else chunk.text)
```

### 2.5.2 Rate Limiting — 速率限制

大模型服务商通常设定调用速率上限，短时间过多请求会收到 429 错误。LangChain 提供 `InMemoryRateLimiter` 在客户端控制请求节奏。

```python
from langchain_core.rate_limiters import InMemoryRateLimiter

rate_limiter = InMemoryRateLimiter(
    requests_per_second=0.1,      # 每10s允许1个请求
    check_every_n_seconds=0.1,    # 每100ms检查一次
    max_bucket_size=5,            # 允许突发5个请求
)

deepseek_llm = init_chat_model(
    model="deepseek-chat",
    model_provider="deepseek",
    api_key=DEEPSEEK_API_KEY,
    base_url=DEEPSEEK_BASE_URL,
    rate_limiter=rate_limiter,    # 绑定速率限制器
)

# 此后调用会自动控制节奏
```

**InMemoryRateLimiter 参数：**

| 参数 | 作用 |
|------|------|
| `requests_per_second` | 每秒允许的最大请求数，如 0.1 表示平均每10秒1个请求 |
| `check_every_n_seconds` | 检查频率的时间粒度，如 0.1 表示每100ms检查一次 |
| `max_bucket_size` | 允许的瞬时突发请求量 |

### 2.5.3 Invocation Config — 调用配置

通过 `config` 参数（类型 `RunnableConfig`）在运行时动态配置模型行为，无需在初始化时固定所有参数。

```python
response = deepseek_llm.invoke(
    "你好",
    config={
        "run_name": "my_run",              # LangSmith 中显示的运行名称
        "tags": ["tag1", "tag2"],          # 标签，便于分类查找
        "metadata": {"user_id": "123"},    # 附加元数据
        "callbacks": [custom_handler],     # 自定义回调函数
        "configurable": {
            "model": "deepseek-reasoner",  # 动态切换模型
            "temperature": 0.7,            # 动态调整温度
            "max_tokens": 100              # 动态限制令牌数
        }
    }
)
```

**config 参数说明：**

| 配置项 | 类型 | 描述 |
|--------|------|------|
| `run_name` | str | 为运行设置可读名称，用于 LangSmith 追踪 |
| `tags` | List[str] | 标签，用于分类和过滤 |
| `metadata` | Dict | 附加键值对元数据 |
| `callbacks` | List | 回调处理器，在不同阶段触发 |
| `max_concurrency` | int | 限制最大并发运行数 |
| `recursion_limit` | int | 限制递归调用的最大深度（Agent 中防无限循环） |
| `configurable` | Dict | 万能字典，传递可配置参数 |

**运行时 config vs 初始化参数：**
- 初始化参数：模型的默认设置，适用于大部分场景
- 运行时 config：单次调用的特定设置，**优先级更高**

**自定义回调示例：**

```python
from langchain_core.callbacks import BaseCallbackHandler

class MyCustomCallbackHandler(BaseCallbackHandler):
    def on_llm_start(self, serialized, prompts, **kwargs):
        run_name = kwargs.get("name")
        tags = kwargs.get("tags", [])
        print(f"[LLM开始] 运行名称: {run_name}, 标签: {tags}")

    def on_llm_end(self, response, **kwargs):
        num_tokens = response.llm_output["token_usage"]["total_tokens"]
        print(f"[LLM结束] 消耗令牌数: {num_tokens}")

custom_handler = MyCustomCallbackHandler()
```
