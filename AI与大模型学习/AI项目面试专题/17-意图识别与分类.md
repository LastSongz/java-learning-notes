# 17 - 意图识别与分类

> AI项目面试专题 | 面向简历：「实现基于wiki知识库的用户意图理解」

## 一、面试官会怎么问？

```
"用户意图是怎么识别的？用的什么方案？"
"意图分了多少类？怎么定义的？"
"用户说了一句话，怎么判断是查知识库还是要执行操作？"
"意图识别不准怎么办？准确率多少？"
"模糊意图怎么处理？比如用户说'帮我看看那个东西'"
```

## 二、什么是意图识别？

```
用户输入 → 提取意图 → 决定后续处理方式

例子：
"订单 SO-001 到哪了"     → 意图：查物流       → 调微组件查物流
"退货流程是什么"          → 意图：查知识库      → RAG 检索 wiki
"帮我创建一个采购单"      → 意图：执行操作      → 调微组件创建采购单
"今天天气怎么样"          → 意图：闲聊          → 直接回答或拒绝
```

## 三、意图分类体系设计

### 3.1 供应链场景意图分类

```
一级分类（大类）
├── 知识查询类（走 RAG）
│   ├── 查询流程/制度（"退货流程是什么"）
│   ├── 查询概念/术语（"什么是安全库存"）
│   └── 查询政策/规则（"供应商准入标准是什么"）
│
├── 业务操作类（走微组件）
│   ├── 查询数据（"查一下订单状态"）      ← 高频
│   ├── 创建单据（"帮我创建发货单"）
│   ├── 修改数据（"把数量改成200"）
│   └── 审批操作（"审批通过这个采购单"）
│
├── 系统导航类
│   ├── 页面导航（"打开库存管理页面"）
│   └── 功能查找（"在哪设置供应商"）
│
└── 其他
    ├── 闲聊（"你好"、"天气怎么样"）
    └── 无法识别 → 兜底回复（"抱歉，我无法理解您的问题..."）
```

### 3.2 意图定义规范

```
每个意图需要定义：
1. 意图名称（英文标识）：query_order_status
2. 中文描述：查询订单当前状态
3. 典型说法（训练样本/示例）：
   - "订单 SO-001 到哪了"
   - "帮我看看 SO-001 的状态"
   - "SO-001 发了没有"
   - "我的订单怎样了"
4. 需要提取的槽位（参数）：
   - order_id（订单号）- 必填
5. 后续动作：调用 queryOrderStatus 微组件
6. 澄清话术："请问您要查询哪个订单？请提供订单号。"
```

## 四、意图识别方案对比

### 4.1 三种主流方案

```
              Prompt 分类        传统分类模型       LLM 直接理解
───────────────────────────────────────────────────────────
原理          把意图列表放         训练 BERT/         LLM 天然理解
              进 System Prompt    FastText 等模型     不需要额外训练
准确率        高（90%+）          高（95%+）         高（90%+）
成本          每次调 LLM API      本地推理免费        每次调 LLM API
延迟          中（200-500ms）     低（10-50ms）      中（200-500ms）
灵活性        改 Prompt 即可      需重新训练         改 Prompt 即可
适合场景      意图经常变          意图固定、量大      复杂场景
```

### 4.2 Prompt 分类实现（推荐方案）

```python
import json
from openai import OpenAI

client = OpenAI()

# 定义意图体系
INTENT_SYSTEM_PROMPT = """你是一个意图识别器。根据用户输入，判断意图类别。

## 意图分类
1. knowledge_query - 查询流程/制度/政策/概念（需要查知识库）
2. query_data - 查询业务数据（订单状态、库存、物流等）
3. create_order - 创建业务单据（采购单、发货单、退货单等）
4. update_data - 修改业务数据
5. approve - 审批操作
6. navigate - 页面导航/功能查找
7. chitchat - 闲聊/打招呼
8. unknown - 无法识别

## 输出格式（严格 JSON）
{"intent": "意图名", "slots": {"参数名": "参数值"}, "confidence": 0.95}

## 示例
用户：订单 SO-001 到哪了
输出：{"intent": "query_data", "slots": {"order_id": "SO-001"}, "confidence": 0.95}

用户：退货流程是什么
输出：{"intent": "knowledge_query", "slots": {"topic": "退货流程"}, "confidence": 0.9}

用户：帮我创建一个采购单，供应商是ABC公司，金额5000
输出：{"intent": "create_order", "slots": {"order_type": "采购单", "supplier": "ABC公司", "amount": "5000"}, "confidence": 0.92}

用户：你好
输出：{"intent": "chitchat", "slots": {}, "confidence": 0.98}
"""

def recognize_intent(user_input: str) -> dict:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": INTENT_SYSTEM_PROMPT},
            {"role": "user", "content": user_input}
        ],
        temperature=0  # 意图识别用 0，确保稳定输出
    )
    return json.loads(response.choices[0].message.content)

# 测试
result = recognize_intent("订单 SO-001 的物流信息")
print(result)
# {"intent": "query_data", "slots": {"order_id": "SO-001"}, "confidence": 0.95}
```

### 4.3 为什么选 Prompt 分类？

```
① 不需要额外训练模型，改 Prompt 就能加新意图
② 准确率够高（GPT-4o 在分类任务上表现很好）
③ 同时完成意图识别 + 槽位提取，一步到位
④ 供应链场景意图数量有限（10-20 个），Prompt 完全能覆盖
```

## 五、槽位提取（参数识别）

### 5.1 什么是槽位？

```
意图识别回答"做什么"，槽位提取回答"对谁做"

"帮我查一下订单 SO-001 的物流"
  意图：query_logistics（查物流）
  槽位：order_id = "SO-001"

"创建一个采购单，供应商是华为，金额5000"
  意图：create_order（创建单据）
  槽位：order_type="采购单", supplier="华为", amount="5000"
```

### 5.2 多轮槽位填充

```
用户：帮我创建一个采购单
系统：识别意图 = create_order，槽位 = {order_type: "采购单"}
      检查必填槽位：supplier（缺）、amount（缺）
系统：好的，请问供应商是哪家？采购金额是多少？
用户：华为，5000块
系统：更新槽位 = {order_type: "采购单", supplier: "华为", amount: "5000"}
      必填槽位已齐 → 调用微组件创建采购单
系统：已创建采购单 PO-20240101，供应商华为，金额 ¥5,000。请确认。
```

## 六、模糊意图与兜底策略

```
情况一：置信度低于阈值（如 < 0.7）
处理：请用户澄清（"您是想查订单信息，还是想创建订单？"）

情况二：多个意图匹配
处理：列出选项让用户选（"您是要查数据还是查流程？"）

情况三：完全无法识别
处理：兜底回复 + 引导（"抱歉没理解，您可以试试问我订单、库存相关的问题"）

情况四：超出能力范围
处理：明确告知（"我目前只能处理供应链相关的问题，其他问题暂时无法回答"）
```

## 七、意图识别准确率优化

```
① Prompt 中放足够多的示例（Few-Shot），每个意图 3-5 个典型说法
② 定期分析误分类案例，补充到 Prompt 示例中
③ 加入用户的典型表达方式（口语化、缩写、行业术语）
④ 区分相似意图：知识查询 vs 数据查询（一个查文档，一个查数据库）
⑤ 记录所有意图识别日志，用于持续优化
```

## 八、面试答题模板

> **Q：用户意图是怎么识别的？**

```
我们用 Prompt 分类方案。把意图体系（10+ 个意图）和示例放在 System Prompt 中，
LLM 同时完成意图识别和槽位提取，输出结构化 JSON。

为什么不用传统分类模型？因为供应链场景意图经常需要新增和调整，
Prompt 方案改一下就能上线，不需要重新训练。

准确率在 90% 以上，对低置信度的走兜底策略让用户澄清。
意图分两大类：知识查询走 RAG 检索 wiki，业务操作走微组件调用。
```

## 关键要点

1. **意图识别** = 判断用户"想做什么"，决定后续走 RAG 还是微组件
2. **槽位提取** = 提取操作参数，多轮对话填充缺失槽位
3. **方案选择** = Prompt 分类（灵活、一步到位、准确率高）
4. **意图体系** = 知识查询 + 业务操作 + 系统导航 + 闲聊 + 兜底
5. **模糊处理** = 低置信度澄清、多意图选择、无法识别兜底
6. **持续优化** = 分析误分类日志，补充 Few-Shot 示例
