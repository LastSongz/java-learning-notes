# 03 - 核心概念进阶

> 第一阶段 · 第3课 | 2026-05-06

## Embedding（向量嵌入）— 把文字变成数字

计算机只认识数字。**Embedding 就是把文字翻译成一组数字（向量）**，保留文字的"含义"。

```
"猫"   → [0.2, -0.5, 0.8, 0.1, ...]  (通常几百到几千维)
"狗"   → [0.21, -0.48, 0.79, 0.12, ...]
"汽车" → [-0.7, 0.3, -0.1, 0.9, ...]
```

**关键特性**：意思相近的词，向量也相近。

```
"猫" 和 "狗" 的向量距离很近 → 都是宠物
"猫" 和 "汽车" 的向量距离很远 → 毫无关系

语义空间示意：
        宠物区
     猫 ●  ● 狗
         |
    食物区         交通工具区
  鱼 ●              ● 汽车
```

### 为什么重要？

这是 RAG（后续课程详解）的基础：

```
你有一堆文档 → 全部转成 Embedding 存起来
用户提问     → 问题也转成 Embedding
计算距离     → 找到和问题最"相近"的文档段落
喂给 LLM    → 让模型基于相关内容来回答
```

## Top-P 和 Top-K — 采样策略

除了温度，模型还有更精细的采样控制：

### Top-K

```
从概率最高的 K 个 Token 中选
K=5 → 只在前5个候选里选，其余全部忽略

例子：下一个 Token 的概率分布
"很好" 35%  ←
"不错" 25%  ←   Top-K=3，只保留这3个
"真好" 20%  ←
"糟糕" 8%
"极差" 5%
...（其余忽略）
```

### Top-P（Nucleus Sampling）

```
从概率累加到 P 的那些 Token 中选
Top-P=0.9 → 选最少的 Token，让它们的概率加起来 ≥ 90%

例子：
"很好" 35%  ← 累计 35%
"不错" 25%  ← 累计 60%
"真好" 20%  ← 累计 80%
"糟糕" 8%   ← 累计 88%
"极差" 5%   ← 累计 93% → 超过 90%，到这里为止
```

### 实际使用组合

```
通常设置：
Temperature = 0.7（有点创意）
Top-P = 0.9（在 90% 概率范围内选）

写代码时：
Temperature = 0（确定性）
Top-P = 1（不过滤）
```

## 幻觉（Hallucination）— 模型"一本正经地胡说"

LLM 最重要的问题之一。

```
你问: "李白是哪个朝代的诗人？"
模型: "李白是宋朝诗人。" ← 错的！是唐朝

更隐蔽的：
你问: "请介绍一下张三丰的《太极拳论》"
模型: 详细编造了一篇看起来很像真的文章 ← 完全捏造
```

### 为什么会产生幻觉？

```
LLM 本质 = 根据上文预测下一个最可能的 Token
它不是在"回忆事实"，而是在"生成看起来合理的文字"

当训练数据中相关知识不足时 → 模型会"编造"连贯内容，而不是说"我不知道"
```

### 如何减少幻觉

| 方法 | 说明 |
|------|------|
| 给上下文（RAG） | 先提供相关资料，让模型基于资料回答 |
| 要求引用来源 | "请标注每句话的信息来源" |
| 降低温度 | Temperature=0 让输出更确定 |
| 多次验证 | 同一问题问多次，看答案是否一致 |
| 让模型说"不知道" | Prompt 中加入"如果不确定，请说不知道" |

## 开源 vs 闭源模型

```
闭源模型（API 调用）          开源模型（可以自己部署）
┌─────────────────┐         ┌─────────────────┐
│ GPT-4o          │         │ Llama 3         │
│ Claude          │         │ Qwen（通义千问） │
│ Gemini          │         │ Mistral         │
│ 文心一言        │         │ DeepSeek        │
└─────────────────┘         └─────────────────┘
只能通过 API 调用             可以下载模型权重
看不到训练过程                可以自己微调
数据会发到服务商              数据留在本地
按 Token 付费                需要自己有 GPU
```

### 怎么选？

```
三个问题：

1. 数据敏感吗？
   敏感（医疗/金融/内部数据）→ 优先开源，本地部署
   不敏感                   → 闭源 API 也可以

2. 需要定制吗？
   需要针对特定领域微调      → 开源
   通用能力就行              → 闭源

3. 预算和算力？
   预算少 + 没有 GPU         → 闭源 API（按量付费）
   有 GPU / 长期大量使用      → 开源（一次性投入）
```

## 常见评测指标

```
MMLU     → 综合知识能力（数学、历史、法律等多学科）
HumanEval → 编程能力（能不能写出正确的代码）
MATH     → 数学推理
GSM8K    → 小学数学应用题
MT-Bench → 多轮对话质量
```

> [!warning] 评测分数 ≠ 实际体验
> 1. 评测题可能被"刷题"了
> 2. 你的具体场景和评测场景不同
> 3. 中文能力和英文能力可能差异很大
> 
> 最好的评测：用你自己的业务场景测试

## Fine-tuning vs Prompt Engineering vs RAG

三种让 LLM 更好地为你服务的方式：

```
Prompt Engineering（提示词工程）
→ 不改模型，通过写好提示词来获得更好的结果
→ 成本：几乎为零
→ 适合：大多数场景
→ 优先级：⭐⭐⭐ 最先尝试

RAG（检索增强生成）
→ 不改模型，给模型外部知识库来参考
→ 成本：中等（需要搭知识库）
→ 适合：需要特定领域知识的场景
→ 优先级：⭐⭐ Prompt 不够用就上

Fine-tuning（微调）
→ 改模型，用你的数据继续训练
→ 成本：高（需要数据和算力）
→ 适合：需要模型改变行为风格/学习特定模式
→ 优先级：⭐ 前两者都不行再考虑
```

> [!important] 经验法则
> 先试 Prompt → 不够用加 RAG → 还不行再考虑微调

## 关键要点

1. **Embedding** = 把文字变成数字向量，保留语义（RAG 的基础）
2. **Top-P/Top-K** = 控制模型从多少个候选 Token 中选（精细控制）
3. **幻觉** = 模型编造看起来合理但不真实的内容（最大风险之一）
4. **开源 vs 闭源** = 数据敏感性、定制需求、预算决定选择
5. **评测指标** = 参考意义有，但不能全信
6. **三种方式** = Prompt → RAG → 微调，由简到繁
