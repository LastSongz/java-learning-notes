# 05 - Transformer 架构

> 第二阶段 · 第2课 | 2026-05-06

## 为什么需要 Transformer？

Transformer 之前，处理文本主要用 RNN（循环神经网络）：

```
RNN 工作方式：一个字一个字按顺序读

  我  →  喜欢  →  学  →  AI  →  输出
  h₁ →  h₂   →  h₃  →  h₄

问题1：必须按顺序读 → 无法并行 → 训练极慢
问题2：读到后面，前面记的信息已模糊 → "长距离依赖"问题
```

Transformer 的突破：**一眼看全部，不要顺序读。**

## 自注意力机制（Self-Attention）— Transformer 的灵魂

**核心思想**：每个词去看所有其他词，按相关性融合信息。

```
句子："我 喜欢 在 公园 里 跑步，因为 它 很 安静"

"它"去跟每个词算相关性：
  公园  → 0.60 ← 最高！它指的就是公园
  安静  → 0.15
  里    → 0.10
  跑步  → 0.08
  ...

→ "它"的新表示融合了"公园"的信息
→ 模型理解了"它"指的就是"公园"
```

## Q、K、V 机制

```
类比图书馆找书：
  Query（Q）= 你的搜索词（"我想找什么"）
  Key（K）  = 书的标签（"我能提供什么"）
  Value（V）= 书的内容（"我的实际内容"）

计算过程：
1. 每个 Token 的 Q × 所有 Token 的 K → 相关性分数
2. 分数过 Softmax → 权重（加起来=1）
3. 权重 × 对应的 V → 加权求和 → 融合了上下文的新表示
```

### 具体例子

```
"小明 喂 了 一只 猫"

"猫"的 Q 和每个词的 K 算分数：
  小明 → 0.10（猫的主人）
  喂   → 0.35（被喂了）
  了   → 0.05
  一只 → 0.20（数量）
  猫   → 0.30（自己）

新的"猫" = 0.10×V_小明 + 0.35×V_喂 + 0.05×V_了 + 0.20×V_一只 + 0.30×V_猫
→ 融合了"被小明喂了"的上下文信息
```

## 多头注意力（Multi-Head Attention）

一个注意力关注一种关系，多个头同时关注不同方面：

```
"小明喂了一只猫"

头1: 关注"谁做了什么" → 小明和喂关系强
头2: 关注"动作对象"   → 喂和猫关系强
头3: 关注"数量"       → 一只和猫关系强
头4: 关注语法结构     → 小明主语、猫宾语

→ 所有头的输出拼接 → 更全面的理解
GPT-3 有 96 个头 → 96 个角度同时理解
```

## Transformer 完整架构

原始 Transformer 是编码器-解码器结构：

```
输入 → [编码器] → 理解输入的表示 → [解码器] → 生成输出

编码器：自注意力 + 前馈网络，重复 N 层
解码器：自注意力 + 交叉注意力（看编码器输出）+ 前馈网络，重复 N 层
```

### 三种变体

```
1. 编码器-解码器（翻译、摘要）→ T5、BART
2. Encoder-Only（分类、提取）  → BERT
3. Decoder-Only（生成、对话）  → GPT、Llama、Qwen、DeepSeek

GPT 只用解码器，通过"预测下一个词"逼迫模型学会理解。
```

## Transformer Block 结构（重复 N 层）

```
输入 Token 向量
  ↓
多头自注意力（所有词互相看）
  ↓ 残差连接 + 层归一化
前馈神经网络（每个词独立过 MLP）
  ↓ 残差连接 + 层归一化
输出

GPT-3: 这个 Block 重复 96 次
每一层在之前基础上进一步理解文本
```

## GPT-3 参数对照

```
参数量:         1750 亿      → 所有 W 和 b 的总数
层数:           96 层        → Block 重复次数
注意力头数:      96 个        → 每层多个角度
Embedding 维度:  12288        → 每个 Token 向量长度
上下文窗口:      2048 Token  → 一次能看多长
词表大小:       50257        → 能识别多少不同 Token
```

## Transformer vs RNN

```
                 RNN                  Transformer
─────────────────────────────────────────────────
处理方式         一个一个按顺序         一次看全部
并行能力         ❌ 无法并行            ✅ 完全并行
长距离依赖       ❌ 容易遗忘            ✅ 直接连接任意两个词
训练速度         很慢                  快（GPU 友好）
计算复杂度       O(n)                 O(n²)
```

### Transformer 的代价

```
自注意力计算量 = 序列长度的平方

n = 1000  → 1,000,000 次计算
n = 10000 → 100,000,000 次（100倍）

→ 序列越长，计算量爆炸式增长
→ 这就是上下文窗口难以做大的根本原因
```

## 补充：参数量中的 W 和 B

### W（权重）— 每个输入的"重要性打分"

```
output = f(x₁×w₁ + x₂×w₂ + x₃×w₃ + b)

w 控制每个输入因素的重要程度：
  w 大 → 这个输入很重要
  w 小 → 这个输入不太重要
  w 为负 → 这个输入起反作用
```

### B（偏置）— 神经元的"基础倾向/门槛"

```
b 和输入无关，是神经元自带的固定值：
  b 大 → 神经元容易被激活（积极）
  b 小 → 神经元不容易被激活（保守）

类比：b 是一个人天生的性格倾向
```

### 参数量怎么算

```
一个神经元（3个输入）：3 个 w + 1 个 b = 4 个参数
一层（500个神经元，每个100个输入）：100×500 + 500 = 50,500 个参数
GPT-3（96层，更宽）：1750 亿个 w 和 b

→ "1750 亿参数" = 1750 亿个需要训练找最优值的数字
```

## 补充：残差连接与层归一化

### 残差连接（Residual Connection）

把输入直接"跳过"中间层，和输出加在一起：

```
输入 x → [计算层] → F(x)
  |                    ↓
  └── 直接跳过去 ──→ (+) → 输出 = F(x) + x
```

**为什么需要**：96 层网络中，原始信号和梯度会在传递中逐渐消失。残差连接给每层开一条"捷径"，保证原始信号不丢失、梯度能传回去。

**"残差"的含义**：网络只需学习 F(x)（在原始输入基础上做什么改动），不需要从头学整个映射，学习难度大大降低。

### 层归一化（Layer Normalization）

把数据标准化，让数值保持合理范围：

```
每层计算后数值可能失控：[0.5, 0.3] → [15.3, -42.7] → [9999, -0.001]

LayerNorm 对每个向量做标准化：
  (每个值 - 均值) / 标准差 → 拉回合理范围

类比：电路中的稳压器，防止电压忽高忽低烧坏电器
```

### 在 Transformer Block 中的位置

```
输入 x
  │
  ├──→ [多头自注意力] → F₁(x)
  │         ↓
  │    LayerNorm(F₁(x) + x)     ← 残差 + 归一化
  │         ↓
  │    [前馈神经网络] → F₂(·)
  │         ↓
  └──→ LayerNorm(F₂(·) + ·)     ← 残差 + 归一化
            ↓
         输出
```

残差连接解决"学不动"，层归一化解决"数值崩溃"，两者配合才能训出 96 层的超深网络。

## 补充：KV Cache（推理加速核心）

### 问题：每生成一个新 Token 都要重算前面所有 Token 的 K 和 V

```
生成"猫 坐在 垫子 上 睡觉"：

步骤1：输入"猫" → 算 Q₁ K₁ V₁                          → 1次
步骤2：输入"猫 坐在" → 重算 Q₁K₁V₁ + 算 Q₂K₂V₂         → 2次
步骤3：输入"猫 坐在 垫子" → 重算全部 + 算 Q₃K₃V₃         → 3次
步骤4：输入"猫 坐在 垫子 上" → 重算全部 + 算 Q₄K₄V₄      → 4次

→ "猫"的 K₁V₁ 算了4次，结果每次一模一样 → 纯浪费
```

### 解决：把算过的 K 和 V 存起来，下次直接取

```
步骤1：算 K₁V₁ → 存缓存
步骤2：K₁V₁取缓存 + 只算 K₂V₂ → 存缓存
步骤3：K₁V₁K₂V₂取缓存 + 只算 K₃V₃ → 存缓存
步骤4：全部取缓存 + 只算 K₄V₄ → 存缓存

→ 每步只算1个新Token的K V，其余从缓存取
→ 100个Token：快约50倍；1000个Token：快约500倍
```

### 为什么只缓存 K V 不缓存 Q？

```
K 和 V：被后续所有 Token 反复查询 → 值得缓存
Q：只有当前步骤自己用一次 → 没必要缓存
```

### KV Cache 和上下文窗口的关系

```
上下文窗口越大 → 要存的 K V 越多 → 显存占用越大
128K Token 的 KV Cache 可能占几GB到几十GB显存

优化技术：
  GQA（分组查询）→ 多个注意力头共享 KV → 缓存缩小 70%
  KV 量化 → 16-bit 压缩到 8-bit/4-bit → 省一半以上
  Paged Attention → 像操作系统管内存一样管理缓存
```

## 关键要点

1. **Transformer** 解决了 RNN 两大问题：不能并行 + 长距离遗忘
2. **自注意力** = 每个词看所有词，按相关性融合信息
3. **Q/K/V** = 查询/键/值，像图书馆找书一样匹配信息
4. **多头注意力** = 从多个角度同时理解，拼起来更全面
5. **GPT** 是 Decoder-Only 架构，通过"预测下一个词"学会理解
6. **上下文窗口受限** = 注意力计算量是序列长度的平方
7. **残差连接** = 捷径保信号，让深层网络能训练
8. **层归一化** = 稳压器防崩溃，让数值保持稳定
9. **KV Cache** = 缓存已算过的 K V，避免重复计算，推理加速几十倍
