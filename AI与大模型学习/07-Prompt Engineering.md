# 07 - Prompt Engineering

> 第三阶段 · 第1课 | 2026-05-06

## 核心原则

把模型当成一个聪明但需要明确指令的新人：**给明确、具体的指令，不要让模型猜。**

## 六大 Prompt 技巧

### 1. 角色设定（Role Prompting）

```
"你是一个有10年教学经验的编程老师，擅长用生活化的例子
 解释复杂概念。请向一个完全零基础的学生解释什么是递归。"

模板："你是一个资深的 [领域] 专家，拥有 [经验]，擅长 [特点]。请 [任务]。"
```

### 2. 提供示例（Few-Shot）

```
Zero-Shot（0个示例）：直接给任务
One-Shot（1个示例）：给1个参考
Few-Shot（几个示例）：给2-5个参考

→ 示例越多，模型越理解你要什么风格
→ 2-3 个示例通常就够
```

### 3. 分步思考（Chain of Thought）

```
在问题末尾加上 "请一步一步思考" 或 "Let's think step by step"

效果：模型会自己拆解问题，逐步推理，准确率大幅提升

数学/逻辑/分析类问题尤其有效
```

### 4. 输出格式控制

```
明确指定输出格式：JSON、Markdown表格、编号列表、YAML

示例：
"请用以下 JSON 格式输出：[{\"language\": \"...\", \"pros\": [...]}]"
→ 结构化输出，程序可直接解析
```

### 5. 约束条件

```
限定：字数、受众、范围、风格、必须包含的要素等

示例：
"- 字数：300-500字
 - 受众：高中生
 - 不要使用专业术语
 - 必须包含至少2个现实例子"
```

### 6. 分解复杂任务

```
❌ 一次性要求太多 → 质量差
✅ 分步来做 → 每步质量高，容易检查修正
```

## 防止幻觉的 Prompt 技巧

```
技巧1：限定信息来源
  "根据以下文章回答。如果文章中没有相关信息，请说'无法回答'。"

技巧2：要求标注可信度
  "每个论点后标注信息来源的可信度：[高/中/低]。不确定的请明确说明。"

技巧3：自我验证
  "先回答问题，然后检查答案是否正确。如有错误请修正并说明。"
```

## 通用 Prompt 模板

```
# 角色
你是一个 [领域] 专家，擅长 [技能]。

# 背景
[描述任务的上下文和背景信息]

# 任务
请 [具体的任务描述]

# 要求
- 要求1
- 要求2
- 要求3

# 输出格式
请用 [格式] 输出结果

# 示例
[可选：给1-3个示例]
```

## 实战示例：模拟面试

```
# 角色
你是一个资深的 Java 面试官，在互联网大厂有8年面试经验。

# 背景
我是一名有2年经验的 Java 后端开发者，正在准备大厂面试。

# 任务
请针对 "HashMap 的底层原理" 这个主题，模拟一场面试。
先问一个基础问题，等我回答后，根据我的回答追问或进入下一个问题。

# 要求
- 从基础到深入，逐步增加难度
- 每次只问一个问题
- 我的回答有误时，先纠正再继续
- 总共问 5 个问题

# 输出格式
每次以 "面试官：" 开头提问
```

## 关键要点

1. **核心原则** = 给明确、具体的指令，不要让模型猜
2. **角色设定** = 让模型以特定身份回答
3. **Few-Shot** = 给示例效果远好于不给
4. **分步思考** = "一步一步来"大幅提升推理准确率
5. **格式控制** = 明确指定输出格式
6. **约束条件** = 限定字数、受众、范围
7. **任务分解** = 复杂任务拆成多步
8. **防幻觉** = 限定信息来源，要求标注可信度
