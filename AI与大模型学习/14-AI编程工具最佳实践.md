# 14 - AI 编程工具最佳实践

> 第五阶段 · 第1课 | 2026-05-06

## 主流工具

```
Cursor        → IDE，基于 VSCode，深度集成 AI（最火）
GitHub Copilot → 插件，老牌 AI 补全
Windsurf      → IDE，类似 Cursor
Claude Code   → 终端 Agent
Cline         → VSCode Agent 插件
Augment       → 理解整个代码库的助手
```

## 核心心态

```
AI 是副驾驶，不是自动驾驶
→ 你是驾驶员，AI 是助手
→ 你要会开车，要能判断 AI 指的路对不对
```

## 三层用法

```
第一层：代码补全 → 写一半，AI 补全
第二层：对话生成 → 描述需求，AI 生成代码
第三层：Agent 模式 → AI 自己读代码、改代码、跑测试
```

## 六大最佳实践

### 1. 写好需求描述

差的："帮我写个登录功能"
好的："用 Spring Boot 写登录接口，接收 JSON，BCrypt 校验，返回 JWT，失败返回 401，参考 UserController 风格"

→ 第7课 Prompt Engineering 的实际应用

### 2. 给 AI 足够的上下文

- 用 @ 引用文件："@UserController 帮我加注册接口"
- 用 .cursorrules 写项目规范（AI 每次自动读取）

### 3. 分步让 AI 做事

❌ 一次做完整电商系统
✅ 分步：表结构 → Entity → 接口 → 测试，每步审查

### 4. 永远审查 AI 代码

```
审查清单：
  □ 逻辑正确？
  □ 边界情况？
  □ 安全漏洞？
  □ 性能问题？
  □ 符合项目风格？
  □ 测试通过？
```

### 5. 让 AI 帮你理解代码

不只是写代码：解释代码 / Code Review / 写测试 / 加注释 / 技术选型

### 6. 善用 Agent 模式

Agent 适合：批量修改、迁移、重构
普通模式适合：解释、小改动、快速问答

## 常见坑

```
1. 盲目信任 → 一定审查
2. 需求模糊 → 多花30秒描述清楚
3. 一次改太多 → 分步改，每步验证
4. 不给上下文 → @文件 + .cursorrules
5. 不用版本控制 → 每步 commit，能回滚
```

## 关键要点

1. **AI 是副驾驶** → 你要审查，不能盲信
2. **需求越精确** → 生成质量越高
3. **给上下文** → @引用 + .cursorrules
4. **分步做** → 每步审查确认
5. **审查清单** → 逻辑、安全、性能、规范
6. **Agent 模式** → 批量修改、重构
7. **版本控制** → AI 改坏了能回滚
