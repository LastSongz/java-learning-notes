# 15 - AI 工作流

> 第五阶段 · 第2课 | 2026-05-06
> 🎓 最后一课

## AI 辅助开发完整工作流

```
收到需求
  ↓
① 理解需求 → AI 帮你分析、澄清模糊点
② 技术方案 → AI 帮你调研、对比选型
③ 写代码   → AI 生成 + 你审查修改
④ 调试修 Bug → AI 分析错误、定位问题
⑤ 写测试   → AI 生成单元测试
⑥ Code Review → AI 审查代码
⑦ 写文档   → AI 生成注释和文档
  ↓
提交代码
```

## 各环节实操

### ① 理解需求

```
产品说："用户希望能更快找到想要的东西"

问 AI：帮我分析这个需求可能的实现方向（搜索优化/推荐/分类/历史记录），
每个方向的优缺点是什么？

→ 把模糊需求拆成具体方向，拿去和产品对齐
```

### ② 技术方案

```
"帮我对比 MySQL LIKE、Elasticsearch、MeiliSearch、PG 全文检索，
数据量 100 万，考虑部署复杂度、查询速度、中文支持"

→ 几秒钟出对比表，省半天搜索
```

### ③ 写代码

```
节奏：
1. 自己写接口定义
2. AI 生成实现（@引用相关文件，给上下文）
3. 审查 AI 代码（逻辑、安全、性能、规范）
4. 跑测试验证
```

### ④ 调试

```
报错信息直接丢给 AI + @相关代码
→ AI 解释原因 + 定位行号 + 修复方案

高级用法：
"这段代码高并发会有什么问题？"
"这个 SQL 大数据量会慢吗？"
```

### ⑤ 写测试

```
"@UserService.java 帮我写单元测试，JUnit 5 + Mockito，
覆盖正常和异常，参考 OrderServiceTest 写法"
```

### ⑥ Code Review

```
"@diff 帮我 Review：逻辑错误？安全漏洞？性能问题？更好的实现？风格一致？"

→ 提交真人 Review 前先让 AI 过一遍
```

### ⑦ 写文档

```
"帮这个方法加 JavaDoc"
"帮我把这个类写成 README"
"这段代码用通俗的话解释一下"

→ 以前最烦的写文档，现在几秒搞定
```

## 什么时候该问 AI / 不该问

```
✅ 应该问：
  - 技术方案对比
  - 重复性代码生成
  - 看不懂的代码解释
  - 报错分析
  - 测试/文档
  - 快速验证想法

❌ 不该问：
  - 核心架构决策（需要自己判断）
  - 安全关键代码（AI 可能忽略）
  - 业务核心逻辑（你更懂业务）
  - 不理解就复制粘贴（要理解再用）
```

## 关键要点

1. **工作流七步** = 需求 → 方案 → 编码 → 调试 → 测试 → Review → 文档
2. **每步都能用 AI**，但每步都需要你审查
3. **模糊需求** → AI 帮你拆解
4. **技术选型** → AI 做初步调研
5. **写代码** → 你写骨架，AI 填实现
6. **文档/测试** → AI 代劳，效率翻倍
