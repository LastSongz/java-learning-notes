# 03 - Vibe Coding 与 AI 编程工程化面试

> 来源：`VibeCoding-AI编程实战课-直播PPT.pdf`。该资料更偏 AI 编程能力、开发范式和工程化约束，适合准备“你怎么使用 AI 提升开发效率”“什么是重度 Vibe Coding”“如何避免 AI 写代码跑偏”等问题。

## 一、核心判断

面试里谈 AI 编程，不要只说“我会用 ChatGPT/Cursor 生成代码”。更好的表达是：我能把 AI 当作工程协作对象，用上下文、规范、验证、工具和多 Agent 工作流，把一次性代码生成变成可控的软件工程流程。

朋友分享的面试经验里有一个重点：作业或现场任务不只是看 AI 生成了什么，更看候选人是否能主导 AI。可以把表达压成一句话：**我负责需求澄清、任务拆解、约束规则、测试验证和风险判断，AI 负责加速实现。**

## 一点五、面试补充经验

### 作业型任务怎么体现“人主导 AI”

- 需求先写成 AC：用 Given / When / Then 明确输入、触发动作和期望结果。
- 实现前先拆计划：把大需求拆成 Plan / Todo，而不是直接让 AI 改全项目。
- 关键路径用 TDD：先写失败用例，再让 AI 辅助实现，最后跑测试闭环。
- 架构题要讲 DDD：说明边界、聚合、领域服务和事务一致性，而不是只贴代码。
- 不确定时提问：在 `AGENTS.md` 或规则中要求 AI 遇到缺失上下文时先问人，不要猜。
- 控制上下文长度：长任务按小步骤推进，每一步保留目标、约束、diff 和验证结果。
- 复盘 AI 输出：说明哪些地方采纳了 AI，哪些地方人工改了，为什么。

### ReAct / Agent 视角

可以把 AI Coding Agent 理解成一个 ReAct 循环：

```text
观察上下文 -> 推理下一步 -> 调用工具 -> 查看结果 -> 修正计划
```

面试时不要把这个讲成玄学。它落到工程里就是：让 AI 先读代码，再提出计划，再小步修改，再跑验证，再根据错误继续迭代。

## 二、AI 编程能力演进

| 阶段 | 特征 | 人的角色 |
| --- | --- | --- |
| Copilot 行内补全 | Tab 接受补全 | 写代码的人 |
| ChatGPT 复制粘贴 | 生成代码片段 | 提问和粘贴的人 |
| Cursor 对话式编程 | IDE 内联编辑、上下文问答 | 需求描述者和审查者 |
| 模型能力质变 | 能理解更复杂仓库任务 | 任务拆解者 |
| Vibe Coding / Claude Code | 代理式编程，AI 可执行多步任务 | 方向控制者 |
| MCP 工具体系 | AI 可连接数据库、GitHub、浏览器等工具 | 工具编排者 |
| 文档驱动 / 规范框架 | 用规范约束 AI 输出 | 规范维护者 |
| Harness Engineering / 多 Agent | 用工具链、验证和团队化 Agent 控制工程质量 | AI 工程管理者 |

## 三、7 个核心技术栈

### 1. Context Engineering

问题：AI 容易“失忆”，对话越长越容易丢规则、丢上下文。

解法：

- 用 `AGENTS.md`、`CLAUDE.md`、`.cursor/rules` 注入稳定约束。
- 把项目结构、编码规范、测试命令、边界条件写成可复用上下文。
- 让 AI 每次从项目规范出发，而不是靠临场提示词。

面试话术：

```
我不会只把需求丢给 AI，而是先给它稳定上下文，比如项目结构、代码风格、测试命令和约束条件。这样 AI 不只是会写代码，而是能按团队工程规范写代码。
```

### 2. Harness Engineering

问题：模型有能力，但没有护栏，容易改错范围、破坏现有逻辑。

解法：

- 明确输入：需求、上下文、验收标准。
- 控制过程：计划、分步执行、范围约束。
- 强制验证：lint、typecheck、测试、人工检查。
- 控制副作用：Git diff、review、权限确认。

面试话术：

```
Vibe Coding 像油门，Harness Engineering 像方向盘和刹车。真正可落地的 AI 编程不是让模型自由发挥，而是用规范、工具和验证流程约束它。
```

### 3. Spec-Driven

问题：没有规范文档，AI 每次都在即兴创作。

解法：

- 需求先沉淀为 spec。
- 明确输入输出、边界条件、异常处理和验收标准。
- 代码实现跟着 spec 走，后续维护也能复用。

### 4. Agent Skills

把重复任务封装成技能，例如：

- 调试某类测试失败。
- 生成固定风格的 PR 描述。
- 整理学习笔记。
- 执行发布前检查。

价值：让 AI 从“通才”变成“熟悉团队流程的专才”。

### 5. Agent Teams

一个人可以指挥多个 Agent：

- 主 Agent：理解目标、拆解任务、汇总结果。
- 子 Agent：并行做检索、测试、迁移、文档等独立任务。

适合大型重构、资料整理、多模块并行验证。

### 6. MCP

MCP 可以理解为 AI 世界的工具接口，让模型连接 GitHub、浏览器、数据库、本地文件、自动化系统等能力。

面试表达重点：

```
MCP 的价值不是多一个插件，而是把 AI 从“只会聊天”变成“能读取真实上下文、调用真实工具、完成闭环任务”的工程系统。
```

### 7. Hooks

Hooks 是生命周期钩子，可以在 AI 执行前后自动检查：

- 执行前：阻止危险命令、检查权限。
- 执行后：跑格式化、测试、lint。
- 提交前：检查 diff、敏感信息、生成文件。

## 四、面试高频问题

### Q1：你平时怎么使用 AI 编程？

```
我会把 AI 当作一个工程协作者，而不是只让它生成代码。通常我会先给清楚上下文和验收标准，让它阅读相关代码后给出方案，再分步实现。实现后必须看 diff，并跑对应测试。对于重复任务，我会沉淀成项目规则或技能，比如固定的调试流程、文档整理流程和提交前检查流程。
```

### Q2：什么是 Vibe Coding？

```
Vibe Coding 是一种更自然语言驱动的编程方式，人更多描述目标、约束和反馈，AI 负责生成和修改代码。但它不能等同于随便聊天生成代码。真正能用于生产的 Vibe Coding 要配合上下文工程、规范驱动、测试验证和工具链，否则很容易跑偏。
```

### Q3：怎么避免 AI 生成错误代码？

```
我会从三层控制：第一是输入层，给清楚项目上下文、边界条件和验收标准；第二是过程层，让 AI 先读代码再改，控制修改范围；第三是验证层，看 diff、跑测试、必要时做 code review。对于高风险动作，比如删文件、改数据库、提交代码，要有权限确认和回滚方案。
```

### Q4：AI 编程能力和普通工程师能力是什么关系？

```
AI 会放大工程师的能力，但不能替代基本功。需求拆解、架构判断、边界条件、测试意识、代码审查，这些还是人的核心能力。AI 编程能力强的人，不只是会提示词，而是能把 AI 纳入工程流程，提高交付速度同时守住质量。
```

## 五、和 Java 后端面试的结合

可以把 AI 编程能力落到 Java 项目里：

- 用 AI 辅助读 Spring Boot 模块结构。
- 让 AI 生成 Controller/Service/Repository 的样板代码，但自己审查事务边界和异常处理。
- 用 AI 帮助补测试，但要确认 mock 是否合理。
- 用 AI 做重构方案比较，但最终由自己控制兼容性和发布风险。

## 关键要点

1. 面试不要只说“会用 AI 工具”，要讲“如何工程化使用 AI”。
2. Context Engineering 解决 AI 失忆。
3. Harness Engineering 解决 AI 跑偏。
4. Spec-Driven 解决输出不稳定。
5. MCP 让 AI 接入真实工具链。
6. Hooks 和测试验证负责兜底质量。
