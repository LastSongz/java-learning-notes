# 09 - RAG 优化面试题

> 来源：飞书文档 `RAG相关的面试题`。已打开折叠块后整理。

## 一、RAG 项目 6 个核心面试点

1. 多模态数据解析。
2. 数据分块策略。
3. 元数据增强。
4. 双索引和混合检索。
5. Rerank 重排。
6. RAG 评估和线上反馈闭环。

## 二、多模态数据策略

### 1. 原则

企业知识库不只有纯文本，还包括：

- 文本。
- 表格。
- 图片。
- PDF 扫描件。
- 公式。
- 图表。

RAG 系统要尽量把这些数据统一进入可检索体系。

### 2. OCR 和解析

资料中提到的工具和模型：

- PaddleOCR：通用图片文字识别。
- Dots.OCR / DeepSeekOCR：复杂版面 PDF 和图片解析。
- GLM-OCR：表格解析能力较强，可输出 JSON。

面试话术：

```
我不会把 RAG 只理解成文本切片。企业知识库里有大量 PDF、表格、截图和公式，所以第一步是解析和结构化。OCR 后会尽量保留标题层级、表格结构、页码、图片说明，再统一保存成 Markdown 或结构化 JSON。
```

### 3. 多模态 Embedding

目标是把文本和图片放入统一向量空间，实现 Any-to-Any 检索。

关键点：

- 图片不要只单独向量化。
- 最好把图片和对应文本标签、标题、上下文组成图文对。
- 图片标签可由多模态模型生成，再人工审核。

## 三、数据分块策略

核心原则：

```text
结构优先，保留语义，不机械按固定 token 数切。
```

按内容类型动态切分：

- FAQ：一问一答作为一个 chunk。
- 政策条文：每条条文作为一个 chunk。
- 有章节标题的文档：按标题层级递归切分。
- 表格、图片、公式：单独处理成独立 chunk。

如果块过大，再做语义切割。LangChain 的 `SemanticChunker` 可以根据句子间向量相似度找断点。

```python
text_splitter = SemanticChunker(
    embeddings=embeddings,
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=85,
    sentence_split_regex=r"(?<=[。？！\n])",
    buffer_size=1,
    min_chunk_size=50,
)
```

面试话术：

```
我不会直接用固定长度切。我们的做法是先按文档结构切，比如标题、章节、FAQ、条文；如果仍然过大，再用语义切分。表格和图片不强行拆成普通文本，而是单独作为结构化 chunk，保留元数据。
```

## 四、元数据增强策略

### 1. 结构型元数据

给每个 chunk 补充：

- `doc_id`
- 文档名。
- 标题路径 `title_path`。
- 章节号。
- 页码。
- 相邻 chunk 关系。
- 数据类型：文本、表格、图片、公式。

### 2. 语义型元数据

离线用模型为 chunk 生成：

- 摘要。
- 关键词。
- 实体。
- 意图标签。
- 歧义消除信息。

### 3. 元数据怎么参与检索

- 前置过滤：用户明确查询某个文档、部门、时间范围时，先过滤再检索。
- 后置过滤：先召回，再按元数据过滤和提升排序。
- 知识目录导航：让 LLM 根据问题定位目录路径，缩小检索范围。
- 多路融合重排：把元数据和 chunk 内容一起交给 Reranker。

## 五、双索引和混合检索

### 1. 双索引

在 Milvus / ES / PostgreSQL 等系统里，可以同时保存：

- 稠密向量：Embedding 生成，捕获语义相似性。
- 稀疏向量 / BM25：捕获关键词、专有名词、编号、术语。

### 2. 多路召回

同一个查询可以并行执行：

- 向量语义检索。
- BM25 / 稀疏检索。
- 元数据过滤检索。
- 目录路径检索。

### 3. RRF 融合

资料中提到用 `WeightedRRFRanker` 做加权 RRF：

```text
score = sum(weight_i / (k + rank_i))
```

特点：

- 基于排名，不依赖绝对分数。
- 不需要复杂归一化。
- 对多路检索结果融合比较稳健。

### 4. 精排

融合后的候选集再进入 Reranker：

- BGE-Reranker：企业通用场景常用。
- Qwen3-Reranker：复杂专业文档、多文档矛盾信息、长文档逻辑排序时更有优势。

## 六、RAG 评估策略

### 1. 上线前评估

检索质量：

- Context Precision：检索内容中真正相关的比例和排序质量。
- Context Recall：是否包含回答所需的关键事实。

答案质量：

- Faithfulness：答案是否被上下文支持。
- Response Relevancy：答案是否回答了用户问题。

可以用 RAGAS 生成测试集或评估：

- 从知识库生成问题和参考答案。
- 手动构建高质量评估集。
- 结合人工审核。

### 2. 上线后评估

在链路中分层拦截：

- 第一层：检索上下文低于阈值时，扩大检索或换策略。
- 第二层：答案忠实度或相关度低于阈值时，重新生成或进入人工审核。
- 多次低分结果进入 Human-in-the-loop。

## 七、Reranker 原理和作用

Reranker 不负责扩大召回，而负责提升召回结果质量。

作用：

- 把真正相关但初排靠后的文档提上来。
- 把语义相似但事实不相关的文档压下去。
- 减少输入 LLM 的上下文噪声。
- 降低幻觉，提高答案相关性。
- 缩短上下文，降低 token 成本和延迟。

面试话术：

```
向量检索解决“先找一批可能相关的”，Reranker 解决“这批里面谁最值得给模型看”。它会把 query 和候选文档放在一起做更深的相关性判断，所以比单纯向量相似度更准确。
```

## 八、TopK 不够导致召回不完整怎么办

场景：100 个人员简介，Top10 无法保证召回所有人。

解决思路：不要用一个模糊语义查询一次性召回，而是基于元数据分区查询与聚合。

步骤：

1. 一人一文档或一人一 chunk。
2. 提取姓名、工号、部门、职位等元数据。
3. 按部门、职位等维度分区查询。
4. 每次查询仍取 Top10，但多次查询覆盖全量分区。
5. 用工号或人员 ID 去重。
6. 最后汇总并生成每人 20 字简介。

## 九、多轮 RAG 客服上下文混乱怎么办

问题：固定保留最近 5 条会混入无关历史，甚至和当前问题矛盾。

优化方向：从固定窗口升级为内容感知的动态记忆管理。

### 1. 记忆分层

- 工作记忆：最近 1-2 轮且与当前问题直接相关。
- 长期记忆：完整历史向量化，进入独立对话记忆库。

### 2. 按需召回

新问题到来时：

1. 用当前问题检索长期记忆。
2. 只召回相关历史片段。
3. 与最近一轮对话共同组装上下文。
4. 本轮 Q&A 再写入长期记忆库。

### 3. 矛盾检测

工作流中增加：

- 记忆路由节点。
- 相关历史检索节点。
- 矛盾/主题检测节点。
- 记忆修正节点。
- 上下文重置节点。

面试话术：

```
我不会固定取最近 5 条，而是做内容感知的记忆管理。当前问题先检索相关历史，只取和当前问题有关的片段。如果检测到用户纠正了之前信息，就更新长期记忆；如果是新话题，就重置工作记忆。
```

## 十、RAG 数据源怎么更新

### 1. 增量更新

适合日常新增、修改、删除。

流程：

1. 解析变更文档。
2. 切片并提取元数据。
3. 根据 doc_id / 文件路径 / 版本号查询旧 chunk。
4. 删除旧向量。
5. 插入新 chunk。
6. 记录更新日志。
7. 定期 compact 回收空间。

### 2. 全量重建

适合：

- 文档大规模变更。
- Embedding 模型升级。
- 索引结构变化。
- 数据质量重整。

生产做法：

- 双集合模式：`active` 和 `building`。
- 新集合构建完成并验证后，通过 alias 原子切换。

```text
knowledge_base_v1 -> 当前在线
knowledge_base_v2 -> 构建中
alias knowledge_base -> v1 / v2
```

## 十一、回答不全面怎么优化

可以从召回、上下文、生成三个层次排查：

召回层：

- 增加多路检索。
- 改进切片。
- 引入元数据过滤。
- 增加 query rewrite / multi-query。

上下文层：

- 同文档邻近 chunk 扩展。
- 同章节上下文拼接。
- Rerank 后再压缩。

生成层：

- 要求模型列出依据。
- 要求覆盖多个方面。
- 低置信度时继续检索。

## 关键要点

1. RAG 优化不是只调 TopK，要从解析、切片、元数据、索引、重排、评估全链路看。
2. 多模态 RAG 要处理 OCR、表格、图片和统一向量空间。
3. 切片优先按结构，过大再语义切分。
4. 混合检索 = 稠密向量 + 稀疏/BM25 + 元数据过滤。
5. Reranker 是精排，不是扩大召回。
6. RAGAS 可评估检索质量和答案质量。
7. 数据更新分增量更新和双集合全量重建。
