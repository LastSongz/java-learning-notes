# 项目二：基于DDD的权限管理系统

> **项目负责人 | 2023.12-2024.05**
> 带团队3人，3个月紧急排期

---

## 📝 明线（简历原文）

### 项目背景

需要支撑数千用户的高并发权限查询场景，同时按租户维度实现数据完全隔离，并对标华为权限管理框架实现精细化权限控制。

### 主要职责

- 担任用户中心子领域项目负责人，主导战略与战术设计，划分用户、角色、菜单、首页、数据维度等聚合边界，将权限校验与用户管理置于同一上下文
- 主导高QPS权限查询接口性能优化：压测发现高并发下响应时间接近5秒，根因定位为索引缺失导致三表关联全表扫描。通过执行计划分析加覆盖索引，结合Caffeine本地缓存+Redis分布式缓存实现二级缓存，前端按角色ID+数据范围缓存用户权限粒度，角色维度独立缓存权限点，缩小缓存体积并降低权限变更时的缓存失效范围。优化后单机QPS从200提升至2000+，P99响应时间降至100ms以内
- 通过网关拦截器将租户ID透传至下游服务请求头，实现前端按租户强制隔离，后端定时任务按需跨租户查询
- 通过TDD方式保证代码质量，单元测试覆盖率90%以上。对静态方法使用适配器模式注入测试，对难以初始化的成员变量通过protected方法重写注入模拟数据
- 负责与华为权限框架组对接，深入阅读框架源码，理清框架建表结构与关联关系，完成框架适配逻辑设计

### 业绩

- 带领3人小团队在3个月紧急排期内完成高质量交付，全量无Bug上线，获2024年度优秀个人与团队荣誉

## 🎯 暗线（面试埋点）

### 埋点1：二级缓存一致性

| 项目 | 内容 |
|------|------|
| **简历描述** | Caffeine本地缓存+Redis分布式缓存实现二级缓存 |
| **追问** | 缓存一致性怎么保证？Redis更新后本地缓存怎么失效？ |
| **回答话术** | 读流程：本地缓存→Redis→DB。数据变更时先删Redis，再删本地缓存（不是更新，是删除），通过失效消息通知各节点。 |
| **二次追问** | 如果删Redis成功但本地删除失败怎么办？多节点情况下本地缓存怎么保证一致性？ |
| **二次回答** | 删Redis成功后，会发失效消息通知各节点，本地缓存收到消息后主动失效。如果消息发送失败，有定时任务兜底扫描过期缓存。下次请求时重新从Redis加载。 |

---

### 埋点2：角色缓存失效策略

| 项目 | 内容 |
|------|------|
| **简历描述** | 角色维度独立缓存权限点，缩小缓存体积并降低权限变更时的缓存失效范围 |
| **追问** | 如果批量变更100个角色的权限，缓存失效策略是什么？逐个删100次？ |
| **回答话术** | 批量变更时，用Redis的批量删除命令一次性处理，不会逐个删。如果量特别大，会考虑分批处理或者暂停缓存直接查数据库。 |
| **二次追问** | 禁用缓存开关期间怎么保证数据一致性？ |
| **二次回答** | 禁用期间直接查数据库，虽然慢一点但数据准确。恢复后主动刷新缓存。 |

### 埋点3：网关拦截器

| 项目 | 内容 |
|------|------|
| **简历描述** | 通过网关拦截器将租户ID透传至下游服务请求头 |
| **追问** | Filter怎么写的？Order多少？从请求哪里读取租户ID？ |
| **回答话术** | 在Spring Cloud Gateway里写了一个Filter，核心逻辑是从原始请求的Header中读取`X-Tenant-Id`，用Gateway提供的API把租户ID附加到转发请求的Header中，继续传递。租户ID是前端页面切换租户时在Header里带上，后端所有服务都从Header里读。 |
| **二次追问** | 如果请求体里也有租户ID怎么处理？Filter能读Body吗？ |
| **二次回答** | 一般不在Body里传租户ID，那样需要完整解析Body影响性能。租户ID统一从Header传递，这是标准做法。 |

### 埋点5：SQL优化

| 项目 | 内容 |
|------|------|
| **简历描述** | 通过执行计划分析加覆盖索引，优化后单机QPS从200提升至2000+ |
| **追问** | 覆盖索引怎么加的？执行计划看哪些指标？什么情况下加索引反而更慢？ |
| **回答话术** | 看type、rows、Extra。type要求ref或const，rows尽量少，Extra里没有Using filesort或Using temporary。加索引在大部分情况下是正向优化，但如果表数据量特别小，索引维护成本反而更高，可能导致更慢。 |
| **二次追问** | 加索引后表锁了多久？有没有在高峰期执行导致线上事故？ |
| **二次回答** | 加索引选择在低峰期执行，确保不影响线上服务。生产环境的DDL操作需要非常谨慎。 |
