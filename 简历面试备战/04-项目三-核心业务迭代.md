# 项目三：海思供应链交付系统 - 核心业务迭代

> **后端开发 | 2021.11-2023.11**
> 侧重业务分析能力与跨部门沟通

---

## 📝 明线（简历原文）

### 项目背景

服务于海思电子元器件全生命周期供应与交付，涵盖需求计划、订单管理、生产制造到内外物流协同的全链路核心业务。

### 主要职责

- 跨部门拉通开发、测试与业务方，完成需求逻辑闭环梳理及复杂业务流的设计对齐，确保业务方与技术方对需求的理解一致
- 承担核心模块的后端研发落地，负责生产环境线上排障与性能调优
- 主导业务规则评审，识别业务逻辑中的冲突与漏洞，推动产品需求优化

### 业绩

- 敏锐排查并修复系统重大隐患，有效规避潜在重大经济损失
- 系统化优化多项低效存储过程与超大SQL，显著提升核心流转链路处理效率

---

## 🎯 暗线（面试埋点）

### 埋点1：跨部门拉通

| 项目 | 内容 |
|------|------|
| **简历描述** | 跨部门拉通开发、测试与业务方，完成需求逻辑闭环梳理及复杂业务流的设计对齐 |
| **追问** | 具体拉通了什么？有没有分歧的例子？最后谁拍板？ |
| **回答话术** | 需求评审时业务方和技术方对某个流程的异常处理不一致。我组织会议逐条过，最后技术方案按我的建议走，但书面记录了双方的原始意见。 |
| **二次追问** | 吵起来过吗？怎么收场的？你拍板的依据是什么？ |
| **二次回答** | 吵过。最终是技术风险评估说话的——谁的方案能保证系统稳定性就按谁的。如果业务方坚持，我会把风险书面化，让对方签字确认。 |

---

### 埋点2：重大隐患排查

| 项目 | 内容 |
|------|------|
| **简历描述** | 敏锐排查并修复系统重大隐患，有效规避潜在重大经济损失 |
| **追问** | 具体是什么bug？怎么发现的？影响范围多大？ |
| **回答话术** | 发现某个关键业务节点没有校验，上游数据异常会直接穿透到下游造成数据污染。修复后补了完整的边界校验。 |
| **二次追问** | 为什么之前没发现？是测试漏了还是需求阶段就没定义清楚？ |
| **二次回答** | 测试环境数据不够真实，上线后才触发真实场景。需求阶段确实没有明确定义这个异常路径的处理方式。 |

---

### 埋点3：慢SQL优化

| 项目 | 内容 |
|------|------|
| **简历描述** | 系统化优化多项低效存储过程与超大SQL，显著提升核心流转链路处理效率 |
| **追问** | 举一个具体例子？优化前后的对比？平时怎么抓慢SQL？ |
| **回答话术** | 深度分页+全表扫描，加了游标分页或者ID范围限制，执行计划从全表扫描变为索引范围扫描，查询时间从秒级降到毫秒级。慢SQL通过公司监控平台抓取。 |
| **二次追问** | 深度分页改成游标分页后，旧代码怎么处理？加索引后表锁了多久？ |
| **二次回答** | 兼容处理，保留旧接口同时提供新接口。加索引选择在低峰期执行，确保不影响线上服务。 |
