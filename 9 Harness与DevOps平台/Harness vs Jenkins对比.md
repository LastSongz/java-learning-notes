# Harness vs Jenkins 对比

> 为什么企业从 Jenkins 迁移到 Harness？核心差异与迁移动因

---

## 📊 全面对比表

| 维度 | Jenkins | Harness |
|------|---------|---------|
| **诞生年代** | 2011（Hudson 更名） | 2016 |
| **架构** | 单体 Java，Controller-Agent | 云原生，容器化，SaaS + 本地部署 |
| **配置方式** | Groovy 脚本（Jenkinsfile） | YAML + 可视化拖拽 |
| **维护成本** | 需要 **2-5 人** 专门维护 | 低维护，自动弹性 |
| **插件生态** | 1,800+ 插件，但**兼容性差** | 150+ 原生集成，无插件冲突 |
| **部署策略** | 需手动编写脚本 | **原生 Canary / Blue-Green** |
| **AI 能力** | ❌ 无 | ✅ AI 回滚、智能测试、成本优化 |
| **安全/合规** | 依赖第三方插件 | **原生 OPA 策略、审计追踪、SLSA L3** |
| **GitOps** | ❌ 无原生支持 | ✅ ArgoCD / Flux 集成 |
| **云成本管理** | ❌ 无 | ✅ 内置 FinOps |
| **SaaS** | ❌ 无（必须自建） | ✅ 主要模式 |
| **多云支持** | 需大量配置 | 原生支持 AWS/Azure/GCP/K8s |
| **总拥有成本** | 免费，但维护人力高 | 付费，但综合成本低 |

---

## 🔥 Jenkins 的 5 大痛点

### 1. 插件地狱（Plugin Hell）
- Jenkins 有 1,800+ 插件，**更新一个可能导致整个构建服务崩溃**
- 插件之间版本冲突是家常便饭
- 安全漏洞频出，更新又不兼容
- 大企业动辄 **80-100 个独立 Jenkins 实例**（如 Ancestry.com 的案例）

### 2. 维护成本指数级增长
- 规模小（几个服务）→ Jenkins 够用
- 规模大（几十上百个服务）→ **需要 2-5 个全职工程师维护 Jenkins**
- 维护工作包括：升级插件、修复构建、管理 Agent、处理磁盘空间等

### 3. 治理能力薄弱
- **没有原生 RBAC** — 靠插件，粒度粗
- **没有审计追踪** — 谁部署了什么、什么时候部署的，难以追溯
- **没有 Policy-as-Code** — 无法统一策略管控
- 对金融/医疗等受监管行业是致命缺陷

### 4. 不适合云原生
- Jenkins 设计于容器/云时代之前
- K8s 支持通过插件实现，不原生
- 弹性扩缩需要额外配置

### 5. 无 AI 能力
- 构建失败需要人工排查日志
- 部署异常需要 on-call 介入
- 测试全量执行，没有智能选择

---

## ✅ Harness 的 5 大优势

### 1. 低维护，高效率
- 容器化架构，自动弹性
- 不需要专门团队维护
- Morningstar 案例：36,000 个 pipeline → **50 个模板**

### 2. AI 驱动的 DevOps
- **Continuous Verification**：部署后 AI 自动监控 + 回滚
- **Test Intelligence**：智能选择需要跑的测试，构建提速 **4-8 倍**
- **AI 失败诊断**：自动分析构建失败原因并给出修复建议

### 3. 企业级治理
- **OPA/Rego Policy-as-Code** — 策略即代码
- **完整审计追踪** — 每个 pipeline/步骤/执行都有记录
- **SLSA Level 3** — 软件供应链安全合规
- **RBAC** — 精细的基于角色的访问控制

### 4. 原生部署策略
- **Canary**（金丝雀）— 逐步放量
- **Blue-Green**（蓝绿）— 双环境切换
- **Rolling**（滚动）— 逐个替换
- 每种策略都配合 CV 做自动验证

### 5. 全链路平台
```
CI（构建+测试） → STO（安全扫描） → CD（部署） → CV（验证） → FinOps（成本）
       一个平台全搞定，不再是工具拼装
```

## 🎯 面试中怎么聊

> **Q：你们为什么从 Jenkins 迁移到 Harness？**

参考回答：
> "主要是因为三个原因：
> 1. **维护成本** — Jenkins 需要专人维护，插件更新经常导致兼容性问题
> 2. **合规需求** — 我们行业有审计要求，Jenkins 的 RBAC 和审计追踪不够用
> 3. **部署效率** — 我们微服务多，需要 Canary 部署和自动回滚，Harness 原生支持"
