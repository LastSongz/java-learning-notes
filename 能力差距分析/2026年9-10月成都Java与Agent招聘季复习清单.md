# 2026 年 9—10 月成都 Java 与 Agent 招聘季复习清单

> 目标：在成都寻找税前现金总包不低于 21 万的高级 Java、Java + AI/Agent 或 Agent 应用开发岗位。
>
> 当前节奏：工作日每天 1—2 小时、周末每天 3—4 小时，按每周约 14 小时规划。
>
> 核心策略：高级 Java 保底，Java Agent 突围，纯 Agent 试探；先把 Flower Chat Agent 做成面试可用的完整纵向 MVP，再用真实面试反馈持续补强。

---

## 一、先记住最终策略

### 1. 投递比例

- [ ] **60% 高级 Java / 资深 Java**：发挥 8 年 Java、供应链/WMS、DDD 重构和复杂业务经验。
- [ ] **30% Java + AI / Java Agent / AI 应用后端**：优先寻找 Java 技术栈接入大模型、Agent、RAG、工具平台的岗位。
- [ ] **10% 纯 Agent 应用开发**：选择接受 Java 转型、重视工程落地而非算法训练的岗位。

### 2. 薪资底线

税前现金总包必须满足以下任一口径：

- [ ] `15K × 14 = 21 万`。
- [ ] `16.2K × 13 ≈ 21 万`。
- [ ] `17.5K × 12 = 21 万`。
- [ ] 优先沟通 `18K—25K` 区间，不只看月薪上限，要确认实际薪数、固定奖金和试用期折扣。

### 3. 个人定位

面试和简历始终围绕下面三层能力展开：

1. **高级 Java 基本盘**：复杂业务建模、DDD 重构、分布式系统、数据库和中间件、稳定性与排障。
2. **AI 工程化差异点**：公司内部供应链 AI 助手 PoC，必须如实说明参与范围和未上线边界。
3. **Agent 作品证明**：个人 Flower Chat Agent 项目，证明自己能把 LangGraph、MCP、RAG、Human-in-the-loop 和 Java 业务服务组成完整系统。

禁止把内部 PoC 与个人项目合并成一个“已生产上线”的项目，也禁止编造准确率、并发量或业务收益。

## 二、市场要求与复习结论

> 招聘信息核对日期：2026-08-10。招聘页面会动态变化，投递时重新确认岗位状态和薪资口径。

### 高级 Java 岗位常见要求

- Java 基础、集合、并发、JVM、线程池和线上问题定位。
- Spring Boot / Spring Cloud、微服务设计、接口与核心模块开发。
- MySQL、Redis、Kafka/RocketMQ、Elasticsearch 等存储与中间件。
- 高并发、高可用、超时、重试、熔断、限流、幂等和数据一致性。
- 技术方案、系统设计、代码质量、测试、文档与跨团队协作。

### Agent 应用岗位常见要求

- Agent 状态、规划、记忆、工具调用和多步骤工作流。
- LangChain / LangGraph / Spring AI / LangChain4j 等框架的实际使用。
- RAG 的解析、切片、向量检索、召回、重排、权限过滤和效果评估。
- Function Calling、MCP、流式输出、错误恢复和人工确认。
- FastAPI 或 Spring Boot 等后端工程能力，而不是只会在 Dify/Coze 里拖流程。
- 生产化意识：权限隔离、可观测性、评测、成本、延迟和稳定性。

## 七、Flower Chat Agent 项目答辩清单

下面的问题不能只背标准答案，必须结合代码、测试和实际运行结果回答：

- [ ] 为什么 Agent 层使用 Python LangGraph，业务规则放在 Java Spring Boot？
- [ ] 为什么用 MCP 暴露业务 Tool，而不是让 Agent 直接访问数据库？
- [ ] 为什么最终业务校验必须放在申请人确认之后？
- [ ] `confirmation_id` 和幂等键分别解决什么问题？
- [ ] LangGraph 中断后如何恢复？服务重启后状态在哪里？
- [ ] JWT 为什么不能保存到 Agent State 或 checkpoint？
- [ ] Tool 参数合法但业务不合法时，错误如何返回给 Agent 和前端？
- [ ] 模型重复调用写 Tool 时如何避免重复创建计划？
- [ ] SSE 断开、模型超时和客户端重连分别怎么处理？
- [ ] Agent 为什么不能自由决定是否跳过审批？
- [ ] RAG 的切片大小怎么定？实际评测发现了什么问题？
- [ ] 如何防止用户检索到其他租户的知识？
- [ ] 为什么保留 Fake Model/Fake Runtime，而不全部调用真实模型测试？
- [ ] 哪些步骤是确定性工作流，哪些步骤才让模型决策？
- [ ] 如果模型完全不可用，系统如何降级？
- [ ] 这个项目与 Dify/Coze 相比多做了什么，少做了什么？
- [ ] 当前方案最大的技术债和下一阶段优先级是什么？
- [ ] VibeCoding 中 AI 生成了哪些代码，哪些关键决策由自己完成？
- [ ] 如何证明自己理解 AI 生成的代码，而不是只会运行？
- [ ] 如果把项目用于真实企业，需要再补哪些安全和运维能力？

验收方式：随机抽取 5 题，每题用 2—3 分钟回答；回答必须包含项目证据和取舍。

## 使用原则

1. 每天只选择当天能完成的 1—2 项，不把勾选本身当作学习成果。
